# Session Memory — 对话记忆持续 + 行为本能提炼

---

## 使用场景

- 单个 Claude Code 窗口有上下文长度上限，长任务中途上下文耗尽后无法继续
- 希望打开新窗口后能接上之前的工作，知道"上次做到哪了、接下来该做什么"
- 希望 Claude 记住自己的思维习惯、协作偏好和关注重点，跨多次会话越来越顺手
- 切换设备或关闭终端后，重新打开时快速恢复工作状态

## 使用方式

```
典型工作流：

窗口 A（工作一段时间，上下文快满了）
  1. /xxy:session-memory save          ← 保存对话 + 采集行为观察
  2. 关闭窗口

窗口 B（新窗口接续工作）
  3. /xxy:session-memory               ← 加载对话记忆 + 行为本能
  4. 继续工作...

积累若干次会话后
  5. /xxy:session-memory distill       ← 从观察中提炼行为本能
  6. /xxy:session-memory evolve        ← 合并相似本能、晋升置信度
```

### 全部命令

| 命令 | 用途 | 频率 |
|------|------|------|
| `/xxy:session-memory save` | 保存当前对话上下文 + 采集行为观察 | 每次收工前 |
| `/xxy:session-memory` 或 `load` | 新窗口加载上次记忆 | 每次新窗口启动时 |
| `/xxy:session-memory status` | 查看记忆和本能状态 | 随时 |
| `/xxy:session-memory compact` | 压缩对话记忆（释放空间） | 记忆文件过大时 |
| `/xxy:session-memory observe` | 手动记录一条用户自知的重要模式 | 发现新的行为模式时 |
| `/xxy:session-memory distill` | 从观察中提炼行为本能 | 积累 10+ 条观察后 |
| `/xxy:session-memory evolve` | 审视本能：合并、晋升、淘汰 | 本能超过 15 条或定期 |

## 使用产出

| 产出 | 说明 |
|------|------|
| `current.md` | 结构化对话记忆：任务进度、决策、文件变更、下一步 |
| `observations.jsonl` | 原始行为观察日志（JSONL 格式） |
| `instincts/*.md` | 提炼后的行为本能，带置信度和证据链 |
| `archive/*.md` | 历次会话归档，不丢失任何版本 |
| `history/*.md` | 对话窗口全量原文存档（不精简、不截断、不遗漏） |

### 本能效果示例

经过多次会话积累和提炼，Claude 会逐步学会：

```
emergent（留意）→ established（主动应用）→ core（始终遵守）

例：用户偏好通过对比表格做技术决策
  emergent:  "观察到用户用表格对比过一次，留个心"
  established: "做技术选型时主动生成对比表格"
  core:      "每次涉及技术选择，默认生成 trade-off 对比表"
```

## 两条路径

1. **对话记忆**：保存/加载对话上下文，解决单窗口上下文上限问题。近期详细，历史可压缩。
2. **行为本能**：从交互中观察并提炼用户的思维模式、行为方式和关注重点，形成跨会话持久的行为准则。

## 存储位置

```
{项目根}/.claude/session-memory/
  current.md            # 对话记忆（每次 save 覆盖更新）
  index.md              # 会话索引
  archive/              # 历史会话归档
  history/              # 对话窗口全量原文存档（不精简不遗漏）
    {YYYY-MM-DD_HH-mm}_{主要内容}.md  # 日期+时分（对话开始的 HH-mm，24 小时制，连字符分隔避免 Windows 冒号禁用）
  observations.jsonl    # 行为观察记录（原始积累）
  instincts/            # 提炼后的行为本能
    {name}.md           # 每个本能一个文件
```

**项目根的确定方式**（动态，不硬编码）：
- 从当前对话窗口的工作目录向上逐级查找，**第一个含有 `.claude/` 目录的祖先目录**即为项目根
- 若当前工作目录本身含 `.claude/`，则当前工作目录就是项目根
- 找到后，所有 `session-memory/` 相关路径都基于该项目根拼接
- 若向上遍历到根目录仍未找到 `.claude/`，则在当前工作目录下创建 `.claude/session-memory/` 并以此作为项目根

首次使用时自动创建目录和初始文件。

## 路径二：行为本能

### 核心思想

不记录"说了什么"，而是从中提炼"学会了什么"。用户的思维模式、行为方式和关注重点会被观察、积累、聚类，最终提炼为行为本能。这些本能在后续会话中指导 Claude 更好地匹配用户的工作方式。

### 观察什么

从对话中识别以下四类行为信号：

| 类别 | 说明 | 示例信号 |
|------|------|---------|
| thinking | 思维模式 — 用户如何分析和决策 | 偏好对比表格、先看全局再深入、追问底层原理 |
| behavior | 行为方式 — 用户如何与 Claude 协作 | 喜欢先看方案再动手、逐层细化、偏好短回复 |
| focus | 关注重点 — 用户反复强调什么 | 安全性、性能、简洁性、可维护性、成本 |
| preference | 具体偏好 — 工具/风格/格式选择 | 用中文沟通、偏好 Kotlin 风格、避免 emoji |

### observations.jsonl 格式

每行一条 JSON，追加写入：

```json
{"ts":"2026-06-12T15:30","cat":"thinking","obs":"通过对比表格分析技术选型，关注 trade-off 而非单一优劣","ctx":"数据库层技术选型讨论"}
```

字段说明：
- `ts`：ISO 时间戳
- `cat`：thinking / behavior / focus / preference
- `obs`：观察到的行为描述（一句话，客观描述，不加评判）
- `ctx`：上下文（在什么场景下观察到）

### instinct 文件格式

每个本能一个文件，位于 `instincts/` 目录下：

```markdown
---
name: {kebab-case-name}
category: thinking | behavior | focus | preference
confidence: emergent | established | core
observed: {观察到此模式的次数}
first: {首次观察日期}
last: {最近观察日期}
---

{一句话行为准则，描述用户的这个模式}

**证据**：
- {observation 摘要 1}
- {observation 摘要 2}

**应用方式**：{Claude 应如何据此调整自己的行为}
```

### 置信度演进

| 级别 | 条件 | 含义 |
|------|------|------|
| emergent | 观察到 1-2 次 | 新出现的模式，可能是偶发，留意但不强制遵守 |
| established | 观察到 3-5 次 | 多次确认的模式，较可靠，应主动应用 |
| core | 观察到 6 次以上 | 核心特征，高度可靠，始终遵守 |

### 本能生命周期

```
对话交互 → 观察(observations.jsonl) → 聚类提炼(instincts/) → 演化(合并/晋升/淘汰)
```

- **观察**：在对话中识别行为信号，记录原始观察
- **提炼**：将相似观察聚类，生成或更新本能
- **演化**：定期审视本能，合并相似的、晋升置信度、淘汰过时的

## 路径一命令

### `save` — 保存对话上下文 + 采集行为观察

**步骤：**

1. **准备目录**
   - 确认 `.claude/session-memory/` 存在，不存在则创建
   - 确认 `archive/`、`history/` 和 `instincts/` 子目录存在
   - 确认 `index.md` 存在，不存在则创建

2. **判断保存模式**
   读取 `current.md`（如存在），检查「已保存轮次」和「会话 ID」：

   - **首次保存**（current.md 不存在）：从头分析整个对话
   - **跨会话保存**（current.md 的会话 ID 与当前对话不同）：
     - 旧 current.md 包含上一个窗口的完整记忆，需要保留合并
     - 将旧 current.md 归档到 `archive/{旧会话ID}.md`，文件顶部附加 frontmatter：
       - `session_id`: {旧会话ID}
       - `archived_at`: {YYYY-MM-DD}
       - `key_files`: [{关键文件列表}]
       - `key_decisions`: [{1-2 条核心决策}]
       - frontmatter 之后接旧 current.md 全文
       - frontmatter 字段从旧 current.md 的决策记录和文件变更提取
     - 从头分析当前对话，与旧记忆合并
   - **增量保存**（current.md 的会话 ID 与当前对话相同）：
     - 这是**同窗口多次 save**
     - 只分析「已保存轮次」之后的新增轮次
     - 不重新归档（同窗口的旧版本已在首次 save 时归档过）
     - 不重新分析已保存的轮次

3. **分析对话**
   根据保存模式决定分析范围：

   **首次保存 / 跨会话保存**：从对话开头到当前消息
   - 识别主任务（一句话概括）
   - 提取最近 10 轮对话的结构化摘要
   - 超出 10 轮的压缩为要点，追加到历史摘要
   - 提取所有决策和文件变更
   - 判断进度，总结下次继续的要点

   **增量保存**：只分析「已保存轮次」之后的新增轮次
   - 更新主任务描述（如有变化）
   - 将新增轮次插入「近期对话」（保持最新 10 轮，溢出的压缩到历史摘要）
   - 追加新的决策和文件变更
   - 更新进度清单和「下次继续」
   - 更新「已保存轮次」为当前总轮次数

4. **采集行为观察**（本能路径）
   审视**本次分析范围内**的用户行为模式：
   - 用户如何提问？（直接命令、探索性、追问式）
   - 用户关注什么维度？（反复提到什么、跳过什么）
   - 用户如何做决策？（需要对比、凭直觉、要数据）
   - 用户偏好什么风格？（简洁、详细、结构化）
   - 将识别到的行为信号追加到 `observations.jsonl`

   **观察标准**：只记录反复出现的模式，不记录一次性偏好。每条观察必须是客观行为描述，不包含主观评价。
   **去重**：追加前检查 observations.jsonl 已有记录，相同行为模式不重复写入。

5. **合并记忆**
   - 「历史摘要」= 压缩合并，不超过 50 行
   - 「决策记录」= 去重合并（同主题只保留最新）
   - 「文件变更」= 同一文件只保留最新操作

6. **写入文件**
   - 写入 `current.md`
   - 更新 `index.md`：
     - **主题**：从「当前任务」提炼一句话
     - **关键决策**：从「决策记录」提取 1-2 条核心决策，分号分隔
     - **涉及文件**：从「文件变更」提取；超过 3 个用"前 3 个 + 等 N 个"
     - **状态**：进行中 / 已归档

7. **全量保存对话原文**
   将当前对话窗口的**全部内容**（每一条用户消息、AI 回复、工具调用及其参数、工具返回结果、系统提示、thinking）逐字逐句写入 `history/` 目录。此步骤是 save 的硬性义务，不可跳过、不可降级为摘要。

   **文件归属规则**：
   - 每个对话窗口对应 `history/` 下的**唯一文件**，文件名格式：`{YYYY-MM-DD_HH-mm}_{主要内容}.md`
     - `YYYY-MM-DD`：该对话窗口**首次保存**的日期（本地时区）
     - `HH-mm`：该对话窗口**开始时间**的时分（24 小时制，本地时区；用连字符 `-` 分隔，**不用冒号**——Windows 文件名禁止冒号）。无法精确获取对话开始时间时，用首次 save 时的本地时分作为近似
     - `主要内容`：任务一句话概括，去掉标点和空格
     - 示例：`2026-06-14_09-30_INTJ友谊讨论.md`
   - **同一对话窗口的所有内容存入同一文件**；**不同对话窗口即使同天或内容相似，也必须各自独立存为一个文件**——HH-mm 时分标志确保同日不同时段的对话可分辨
   - 归属判断机制（必须按此执行，不可凭文件名猜测）：
     1. 从 `current.md` 读取当前「会话 ID」（格式 `{YYYY-MM-DD}_{三位序号}`）
     2. 扫描 `history/` 下所有 `.md` 文件，**读取每个文件顶部 frontmatter 的 `session_id` 字段**
     3. 若存在 `session_id` 与当前会话 ID 完全一致的文件 → 续写到该文件
     4. 若无任何匹配 → 创建新文件，并在 frontmatter 写入当前会话 ID
   - 文件名本身不含会话 ID，**禁止用文件名做归属判断**；只有 frontmatter 的 `session_id` 是权威依据

   **文件 frontmatter 格式**（新建时写入；每次续写时更新 `last_saved` 和 `turn_count`）：
   ```
   ---
   session_id: {YYYY-MM-DD}_{三位序号}
   first_saved: {YYYY-MM-DD HH:mm}
   last_saved: {YYYY-MM-DD HH:mm}
   turn_count: {已保存到第几轮}
   ---

   # 对话全量原文 · {主要内容}

   > 本文件为该会话窗口的逐字原文存档，禁止精简、压缩、改写。
   ```

   **分批续写规则**：
   - 对话内容过多时，**在同一文件内分批追加写入**，**禁止**拆分为 `part1.md`、`part2.md` 等多个文件
   - **批次单位**：以"对话轮次"为单元，一轮 = 一次用户消息 + 对应的全部 AI 回复（含所有工具调用、工具结果、thinking）。每批固定 **5 轮**
   - **首次保存**：用 Write 创建文件（含 frontmatter + 标题 + 第一批 5 轮），后续批次用 Edit 在正文末尾追加
   - **增量 save**：先读取 frontmatter 的 `turn_count`，只追加该数值之后的新增轮次；批次仍按每 5 轮切分
   - 每批追加完成后，同步更新 frontmatter 的 `last_saved` 和 `turn_count`

   **严格要求**：
   - **禁止精简、压缩、摘要、改写**——必须是逐字逐句的原文，包括错误信息、重复内容、冗长输出
   - **禁止遗漏任何轮次**——用户消息、AI 文本、工具调用名+参数、工具返回结果、系统提示、thinking 块，一项都不能少
   - **工具调用的写入格式**：保留工具名、完整参数（含 file_path、pattern 等关键字段）、完整返回结果；返回结果过长时**也不得截断**，必须原样写入
   - **每批写入后立即读取回验**（强制流程，不可省略）：
     1. 用 Read 读取刚追加的批次范围
     2. 与对话原文中对应轮次**逐字对比**：行数、字符数、工具名、文件路径、关键标识符必须完全一致
     3. 不一致 → 判定该批写入失败，删除该批重写，再次回验，直到通过
   - **全部批次追加完成后执行全局校验**：
     1. 读取整个 history 文件
     2. 按对话轮次顺序逐轮对照对话原文
     3. 输出校验结果：`通过 {n}/{total} 轮` 或 `失败：缺失第 X、Y 轮，第 Z 轮内容被篡改`
     4. **校验未通过时禁止报告"保存成功"**——必须先修复缺失/篡改的轮次
   - 校验通过后在 save 报告中明确列出：文件路径、覆盖轮次、校验结果

8. **输出报告**
   ```
   ## 会话记忆已保存

   ### 对话记忆
   | 项目 | 内容 |
   |------|------|
   | 会话 ID | {id} |
   | 对话轮次 | {n} 轮（近期保留 {m} 轮） |
   | 决策数 | {n} 条 |
   | 文件变更 | {n} 个文件 |
   | 归档 | archive/{旧id}.md |

   ### 全量存档
   | 项目 | 内容 |
   |------|------|
   | 文件 | history/{YYYY-MM-DD_HH-mm}_{主要内容}.md |
   | 会话 ID | {与 current.md 中的会话 ID 一致} |
   | 轮次覆盖 | {n}/{total} 轮 |
   | 校验结果 | {通过 / 缺失：第X轮、第Y轮} |

   ### 行为观察
   | 项目 | 内容 |
   |------|------|
   | 新增观察 | {n} 条 |
   | 累计观察 | {n} 条 |
   | 已提炼本能 | {n} 条 |

   {如有新增观察}建议在积累足够观察后执行 `/xxy:session-memory distill` 提炼本能。
   ```

## 路径二命令

### `observe [观察描述]` — 记录行为观察

手动或自动记录一条行为观察。

**步骤：**

1. **有参数时**（用户提供了描述）：
   - 解析描述，判断类别（thinking/behavior/focus/preference）
   - 追加一条记录到 `observations.jsonl`

2. **无参数时**（让 Claude 回溯分析）：
   - 回顾当前对话中用户的行为模式
   - 识别值得记录的观察（非一次性的、有规律的模式）
   - 每条观察追加到 `observations.jsonl`

3. 输出：
   ```
   ## 已记录 {n} 条观察

   | # | 类别 | 观察 |
   |---|------|------|
   | 1 | {cat} | {obs} |
   | ... | ... | ... |

   累计观察：{total} 条。{如有 > 10 条未提炼}建议执行 `/xxy:session-memory distill`。
   ```

### `distill` — 提炼行为本能

从积累的观察中聚类、提炼或更新行为本能。

**核心约束（不可违背）**：本能文件的生成/更新必须**逐条让用户确认**，**禁止静默写入**。先输出候选清单，用户逐条确认后才写入。

**步骤：**

1. 读取 `observations.jsonl`，解析所有观察记录
2. 读取 `instincts/` 目录下已有本能（如有）
3. **聚类分析**：
   - 按类别（thinking/behavior/focus/preference）分组
   - 在每组内找相似观察（描述同一模式的不同实例）
   - 每个聚类 = 一个潜在本能
4. **生成候选清单**（仅生成，不写入）：
   - **新聚类**：建议创建本能（confidence = emergent），附拟定内容
   - **已有本能匹配新观察**：建议更新（observed+N、更新 last 日期、追加证据、按计数晋升 confidence：>=6 core / >=3 established / <3 emergent）
   - **孤立观察**：建议保留在 observations.jsonl
5. **输出候选 + 逐条确认**（必须等用户确认，禁止静默）：
   - 列出每个候选（类型/名称/类别/拟定内容或变更摘要）
   - 用户逐条确认：创建 / 更新 / 保留 / 调整措辞 / 否决
   - **未获明确确认的不写入**
6. **写入确认的本能**：对用户确认的创建/更新，写入/更新 `instincts/` 下文件
7. **不删除 observations.jsonl**——原始观察保留作为证据链
8. 输出报告（已确认并写入的本能 + 未确认/否决的）：
   ```
   ## 本能提炼完成

   ### 新增本能
   | 名称 | 类别 | 置信度 | 观察数 |
   |------|------|--------|--------|
   | {name} | {cat} | emergent | {n} |

   ### 更新本能
   | 名称 | 置信度变化 | 观察数变化 |
   |------|-----------|-----------|
   | {name} | emergent → established | +2 |

   ### 未聚类观察
   {n} 条孤立观察保留，等待更多证据。

   ### 当前本能概览
   | 名称 | 类别 | 置信度 | 观察数 |
   |------|------|--------|--------|
   | {逐条列出所有本能} |
   ```

### `evolve` — 演化行为本能

定期审视所有本能，合并、晋升、淘汰。

**触发建议**：当本能总数超过 15 条，或距上次 evolve 超过 5 次会话时。

**核心约束（不可违背）**：合并/晋升/精简/淘汰等所有变更必须**逐条让用户确认**，**禁止静默写入**。先输出候选清单，用户逐条确认后才执行。

**步骤：**

1. 读取 `instincts/` 下所有本能文件
2. **生成候选清单**（仅生成，不执行）：
   - **合并候选**：相似本能（同模式不同方面）建议合并（observed 求和、证据/应用方式合并、删被合并文件）
   - **晋升候选**：按 observed 计数建议 confidence 晋升（>=6 core / >=3 established / <3 emergent）
   - **淘汰候选**：`last` 超 30 天且 confidence 为 emergent 的本能
   - **精简候选**：证据超 5 条的建议精简（保留最近 5 条）
3. **输出候选 + 逐条确认**（必须等用户确认，禁止静默）：
   - 列出每个候选（类型/涉及本能/拟定变更/原因）
   - 用户逐条确认：执行 / 调整 / 否决
   - **未获明确确认的不执行**
4. **执行确认的变更**：
   - 合并：合并确认的本能（observed 求和、证据/应用方式合并、删被合并文件）
   - 晋升：更新确认的 confidence
   - 淘汰：删除确认的本能文件
   - 精简：精简确认的证据
5. 输出报告（已确认并执行的 + 未确认/否决的）：
   ```
   ## 本能演化完成

   ### 合并
   {name-A} + {name-B} → {name-merged}

   ### 晋升
   | 本能 | 变化 |
   |------|------|
   | {name} | emergent → established |
   | {name} | established → core |

   ### 候选淘汰
   | 本能 | 最后观察 | 原因 |
   |------|---------|------|
   | {name} | {date} | 30 天未观察，emergent 级别 |

   {如有候选}确认后执行 `/xxy:session-memory evolve --confirm` 淘汰。
   {无候选}所有本能状态良好。

   ### 当前本能（{n} 条）
   | 名称 | 类别 | 置信度 | 观察数 | 最后观察 |
   |------|------|--------|--------|---------|
   | {逐条列出} |
   ```

## 渐进细节规则

### 对话记忆

| 层级 | 范围 | 保留策略 | 行数预算 |
|------|------|---------|---------|
| 近期对话 | 最近 10 轮（compact 后 5 轮） | 完整结构：意图 + 行动 + 产出 | 每轮 3-5 行 |
| 会话概要 | 当前任务 / 进度 / 决策 / 变更 | 结构化表格 | 合计 ~30 行 |
| 历史摘要 | 10 轮之前的全部对话 | 压缩为连贯段落 | 50 行以内 |

### 行为本能

| 层级 | 条件 | 应用策略 |
|------|------|---------|
| emergent | 1-2 次观察 | 留意但不过度调整行为 |
| established | 3-5 次观察 | 主动应用到相关场景 |
| core | 6+ 次观察 | 始终遵守，作为默认行为准则 |

### 压缩优先级（对话记忆）

1. **决策及原因** — 永不删除，除非被后续决策取代
2. **未完成事项和下一步** — 直接决定工作连续性
3. **文件变更** — 知道改了什么文件
4. **近期对话详情** — 最近的工作上下文
5. **历史操作细节** — 最先压缩

## 注意事项

- 所有路径基于「项目根目录」——按本章「存储位置」一节定义的方式动态确定（从当前工作目录向上查找含 `.claude/` 的祖先目录），**不硬编码任何绝对路径**
- 每次 save 自动归档上一版 current.md 到 `archive/`
- 文件使用 UTF-8 编码
- **不自动保存**——只在用户显式调用命令时才操作文件系统
- load 后的记忆和本能作为工作上下文，按需引用
- 如果用户连续多次 save 而没有新对话轮次，提醒
- 不要在非 session-memory 相关的回复中提及或操作会话记忆文件
- **本能系统的观察必须客观**——描述"用户做了什么"而非"用户是什么样的人"
- **本能不等于记忆**——本能是跨项目的行为模式，不记录项目特定的事实
- evolve 的候选淘汰需要用户确认，不自动执行
