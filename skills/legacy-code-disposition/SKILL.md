# legacy-code-disposition — 遗留代码处置决策

## 何时使用
遇到一段"似乎没用"的代码，需要决定怎么处置：
- 未被调用的函数/方法
- 被注释掉的逻辑块
- 空实现/返回占位值的接口
- **算了却没接入主流程的半成品**（典型：`val x = compute()` 后面用的却是原始值）
- 标了 TODO/FIXME 长期未动、已不确定还要不要的代码

不适用：明确的临时调试代码（直接删）、刚写还在用的代码。

## 和其他工具的区别
- **code-review / 代码审查**：审查找问题（这段有什么 bug）。本 skill 是**已知没用**，决定删/留/接通。
- **dev-recap-docs**：产出理解文档。本 skill 产出**处置动作**。
- 先用本 skill 决定"删/留/接通"，再用 dev-recap-docs 记录。

## 产出
一个有依据的处置决策 + 执行（删除/接通/保留标注），决策理由可追溯。

## 方法论（6 步）

### 1. 确认是否真未使用
全仓搜引用点（定义 + 所有调用处）。区分两种"没用"：
- **算了没用**（半成品）：计算/定义了结果但没接入 → 可能功能缺失
- **评估后移除调用**（被证伪）：曾调用，后因方案变更移除 → 可能确实不需要

提交历史能区分：调用是"从未加过"还是"加过又删"。

### 2. 追溯原始设计意图
从注释 / 提交历史 / 设计文档还原本该在哪、做什么、为什么写。注释里的"为了 X / 防止 Y / 触发 Z"是设计动机。

### 3. 构建现状证据链
列出它**本该接入的每个出口**，逐一确认是否真没接：
- 防"看似没用，其实在别处间接生效"（反射/配置/回调调用）
- 每个出口给"确认没接"的证据（grep 无引用 / 流程跳过 / 用了替代值）

### 4. 验证动机是否经实证
设计意图（第2步）里的"可能 / 推测 / 会导致 X"——
- 是否在日志 / 文档 / 实测记录中有**实证**？还是只是预防性推测？
- 系统当前（不接这段代码）**能否正常跑通**？能跑通 → 动机可能已被现实证伪。

> 关键：注释里的"可能不兼容 / 可能导致 X"常是写时的预防推测，未经实证。若实测系统正常，该预防可能不成立。

### 5. 给决策（三选一）
| 决策 | 条件 | 动作 |
|------|------|------|
| **删除** | 动机未经实证 + 实测证明不需要 + 无未来复用价值 | 删代码 |
| **接通** | 半成品（算了没用），本该生效，是功能缺失 | 补上接入，让它真正工作 |
| **保留预案** | 未来可能需要 / 不确定 | 保留 + 标注"未用 + 触发条件"，不静默 |

### 6. 记录决策依据
删除/保留理由写进文档（设计文档 / 提交说明 / 代码注释），可追溯。
- 删除：记"曾实现 X，因 Y 判定不需要（实测 Z），已删"
- 保留预案：记"未用，触发条件 X 时启用"

## 红线
- **禁凭"看起来没用"直接删**——必须走完证据链（第3步），防误删间接生效的代码
- **禁把"预防性推测"当"已证实问题"**——第4步必须区分
- **禁删了不留记录**——第6步必做，否则未来重复纠结

## 实践参考：一次完整处置（已脱敏）
1. **确认未使用**：grep 全仓，定义处 + 一处"算了没用"的调用（构造了结果变量，后续发送/缓存都用原始值）
2. **设计意图**：注释说"清洗某字符串，防对端解析库不认扩展字段→丢弃→卡住"
3. **证据链**：本该接入的出口（发送、缓存后刷新）逐一确认都用原始值，结果从未引用
4. **动机实证**：搜遍联调文档无"卡住"实证（动机是写时推测）；加了兜底配置后实测系统能正常连通
5. **决策**：删除（动机未实证 + 实测不需要）
6. **记录**：理由写入设计文档对应章节 + 提交说明

以上是一次实例，不是方法论本身。
